# 业务链路：让客服回复有履约依据

客户问“现在可以发货吗”，客服可能拿到某天的库存、运营补货建议和外箱唛准备状态。这些事实各有用途，但不能直接证明该客户订单已经拣货、出库或发运。本轮完成独立的事实核验与草稿场景，并向真实 CRM 草稿/预览增加可选服务端端口；验证范围见 [04-verification.md](04-verification.md)。

## 三个项目怎样相连

实习重构项目体现可信采集与更新；个人供应链项目提供库存查询、补货参考、人工采购与表单核验；CRM 二次开发把可读事实变成客服可复核的说明。实际跨项目接线是本 CRM 场景向第二项目发出只读 HTTP 请求，并非完整 ERP 或三套生产系统集成。

| 事实或动作 | 能支持的判断 | 不能推导的结果 |
| --- | --- | --- |
| SKU 库存快照与日期 | 某天、某范围内的现存量 | 实时可分配量、订单预留或发货承诺 |
| 补货参考 | 规则给出的运营建议 | 采购已经执行或供应商已到货 |
| 人工采购 confirmed | 采购意向已确认 | 供应商收单、到货入库、客户订单出库 |
| 外箱唛已有值 | 同 SKU 的准备字段存在 | 客户订单关联、出库、物流或签收 |
| CRM 草稿及缺口 | 帮助客服判断如何回复、继续找谁核实 | 自动消息发送或正式履约审批 |

当前 viewer reader 读取前三类中的库存、补货参考，以及表单准备字段；**不读取采购事实**。采购 confirmed 仅作为规则类型与反例说明，不作为实际 HTTP 演示已获得的事实。

## 一次实际处理

1. 客服在独立本地页面选择合成 SKU 和核对模式。请求只包含固定范围的 SKU/模式，不接受浏览器注入事实。
2. Pi 的实际工具循环调用 `read_operational_evidence`。reader 以 viewer 身份向第二项目登录，读取库存、补货建议及预先映射的准备记录；无采购、表单修改或发送工具。
3. `evidence.ts` 严格校验结构、组织、SKU、时间和时效；不一致时关闭事实输出，部分读取失败时保留可用事实及缺口。服务地址固定为本机 origin，远端重定向被拒绝。
4. 工具结果返回实际 Pi SDK；官方 Faux provider 读取观察后调用确定性渲染，生成待复核草稿。SDK 与工具调用是真实执行，provider 是脚本，没有真实 LLM 调用。
5. 页面显示来源、实际 HTTP 取得时间、业务核对日、风险、下一步与草稿。人工复核只标记本机内存草稿；发送及 CRM 持久化始终为 false。

草稿最多保留 30 分钟，服务重启后丢失；这不是持久化审批系统。未知订单归属、库存分配、实际出库及物流状态仍交人工核对，独立场景不自动发消息。

## 两种时间口径

`current_check` 用当前真实日期检查上游固定快照。上游数据业务日为 2026-09-03，过期时库存不会进入有效事实或被说成当前量；页面仍明确显示取得时间和过期原因。

`historical_replay` 以 2026-09-03 为评估日，仍实际读取当前运行的第二项目合成数据，保留真实 HTTP 取得时间。`AUD-001` 返回历史现存 18、补货参考 72，并核对同 SKU 的 `R-1001` 外箱唛字段；`DEM-001` 可读取历史现存 5。它是固定业务日的回放，不能拿这组数值回答今天能否发货。

即使历史库存有效且外箱唛存在，草稿也只说明核对到的准备信息，并继续要求核实订单关联、分配与物流。采购 confirmed 和外箱唛完成都不代表发货，且实际 reader 未取得采购状态。

## 真实 CRM 接线到哪里

服务端可向 `generateReplyDraft` 传入 `operationalEvidence`，经 preview 传入 `inbound-turn` 的 `buildOpening`，由 `operational-opening.ts` 校验并追加到动态用户上下文，不替换稳定系统规则。没有传入时返回原 opening，原行为保持不变。

这是可选服务端端口。原 CRM UI 没有事实导入控件，公共 API 不接受客户端运营事实，本轮也没有重新运行完整 Supabase、正式会话或客户发送链路验收。独立页面通过不能代替完整 CRM 端到端通过。

## 可以复核的反例

| 反例 | 实现的处理 |
| --- | --- |
| 只有采购 confirmed 或外箱唛字段存在 | 仍不能承诺发货或发送；保留订单与物流缺口 |
| SKU/组织/准备记录不匹配 | 拒绝混用事实，交人工核对 |
| 库存过期、日期未来或晚于采集日 | 不把该库存作为有效当前依据 |
| HTTP 登录失败、超时或返回畸形数据 | 显示读取失败，不补造事实 |
| 部分读取成功 | 保留已验证依据并展示其余缺口 |
| 试图跨源或修改业务 | reader 限制本机固定读取路径，无相应写工具 |

具体测试、浏览器与跨项目实测记录统一保存在 [验证说明](04-verification.md)。
